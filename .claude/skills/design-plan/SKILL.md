# /design-plan <題目>

実装計画を策定するスキル。コードは書かない・実装しない。read-only で調査し、plan.md に計画を書く。

## 手順

1. **既存 plan.md チェック**: ルートに `plan.md` が存在するか確認。存在する場合は「実装中の計画があります」と内容の先頭を表示し、上書きしてよいかユーザーに確認する。拒否されたら中止。

2. **調査**: 題目に関連するコードを Grep / Read / Glob 等で調査する。**ファイルの編集・作成は plan.md のみ**。コードには一切触れない。

3. **plan.md 作成**: ルートに `plan.md` を作成。以下の構成で記述:

```markdown
# <題目>

## 目的
<何を達成するか、背景・動機>

## 変更対象
<影響するファイルを列挙。各ファイルに何をするかを 1 行で。ファイルは編集しない>

## 実装ステップ
<順序付きの具体的な作業ステップ>

## エッジケース・テスト方針
<考慮すべき境界条件、テストの書き方・確認方法>

## 未解決の論点
<判断が必要な点、トレードオフ、代替案>

## Codex レビュー反映
(/plan-review で Codex レビューを行った際、各ラウンドの反映履歴をここに追記)
```

4. **案内**: plan.md 作成後、以下を表示して停止:

> plan.md に計画を書きました。`/plan-review` で Codex にレビューさせることができます。

## 注意
- plan.md は .gitignore に登録されており git には含まれない
- plans/ ディレクトリの git 管理方針は保留中 (おぽさん判断待ち)
- このスキルは調査と計画策定のみ。実装は別途指示で行う
- この skill は Secretary System 非依存。単体プロジェクトでもそのまま動作する (汎用 skill)
